# Design documentation

This section shows the design process behind the program: analysis → design → build → evaluate. A peer should be able to rebuild the course from these documents without asking questions.

| Document | What it covers |
|---|---|
| [Needs analysis](needs-analysis.html) | Performance gap, root causes, constraints, critical behaviors |
| [Personas](personas.html) | 3 workplace + 2 school personas (fictional) |
| [Learning objectives](learning-objectives.html) | Observable objectives with condition, behavior, criterion |
| [Alignment matrix](alignment-matrix.html) | Every objective → content → practice → assessment → framework |
| [Framework mapping](framework-mapping.html) | Coverage of AILit domains/competences and Article 4 considerations |
| [Design decisions](design-decisions.html) | What was decided, alternatives, rationale, evidence |
| [Evaluation plan](evaluation-plan.html) | What is measured, at which LTEM tier, with which method |
| [Evaluation report](evaluation-report.html) | What was done, what it can and can't show, what changed |

Evaluation methods and their status (done / pending) are documented in detail in the repository's `evaluation/METHODS.md`.
